# XP, activity provenance and persistence audit

Baseline: `a01e74172cb266896cb1ee85d508560a5660eaad` (Progression 1.1.5), on `audit/technical-checkup-1.1.6`.
Target inspected: Minecraft 1.21.1, NeoForge **21.1.262**, Java 21. This note describes the XP/persistence portion of the shared audit; other notes cover commands, titles, skills and arena scaling.

## Existing behavior checked and preserved

- The default direct XP curve is `1000 × current level`; reaching level 100 costs **4,950,000 XP**. The iterative grant consumes only the XP required to reach a ceiling, carries excess across levels and never adds an unbounded grant to the existing XP in one operation. The fixture checks several level crossings and `Long.MAX_VALUE` at a nearby ceiling. The ceiling/team lookup is now reused throughout one grant rather than repeated for every crossed level.
- Source XP still pays through the same character bar, fractional remainder and source accounting. Removed automatic crafting/engineering awards remain disabled. Quest commands remain reusable; named `rewardOnce` claims remain distinct and are recorded only after actual payout. No new reward grants or XP balance changes were introduced.
- Combat shares use final post-absorption damage, capped at pre-hit health. Offline/distant contributors remain in the denominator; total credited damage is compared with max health to prevent a token hit receiving the environmental portion. Spawn-egg, dispenser, command, breeding, summon and split exclusions remain, with the existing verified-arena command-spawn exemption.
- Natural mining receipts are dimension + 16³-section bitsets, with legacy placed-position tombstones still honored. Placement, fluid generation and piston source/destination positions remain protected. Silk touch can pay for the first natural break; subsequent placement/breaks cannot pay again through the covered hooks. Logs have no direct XP by default; configured rewarding log blocks are covered by the same placement checks. A real target `PistonStructureResolver` fixture verifies mineral source/destination receipts.
- Vanilla pumpkins/melons use `PushReaction.DESTROY` in the target game; they are not a movable-piston farming exploit. Legitimate regrown fruit/crops and harvest cooldowns remain supported.
- Vanilla fishing keeps hook owner, minimum age, open-water option, paid-hook and player-clock checks. Starcatcher keeps its own catch ownership, removal/completion, cancel/empty-drop and golden metadata checks, with one paid marker per bob. No vanilla-plus-Starcatcher duplicate award is introduced.
- The supplied actual Starcatcher **3.1.4.1** NeoForge 1.21.1 JAR (`SHA-256 4114eba0769936c354cf946b6089c9d17be02b7537c86f6758ebd525c773f8b4`) was inspected with `javap`: `SCDataAttachments.FISHING_BOB`, `FishingBobAttachment.getUuid`, public `FishingBobEntity.player`/`fpToFish`, `CaughtFishInfo.rarity`, and `FishApi.spawnFishFromPlayerFishing(ServerPlayer,boolean,int,boolean,boolean,int)` match the bridge. No stubs were used.
- Standard furnace IItemHandler automation calls the same inventory methods used by the ownership invalidation hooks. Mods mutating backing lists directly, or generating blocks without the placement/fluid/piston events, still require their own integration; this audit does not intercept all world block writes.

## Persistence design and evidence

Character state is **UUID-keyed overworld SavedData**, not an entity attachment. A death clone, End return or reconnect resolves the same `player:<UUID>` compound; an additional `PlayerEvent.Clone` copy would be redundant and could duplicate/migrate state twice. This includes level, XP, skill entitlement inputs, origins/ascension, title ownership/selections and claims. The disposable fixture constructs a replacement `ServerPlayer` with the same UUID and checks shared profile identity, then deep-copy round-trips the complete profile through `ProgressionData.save/load` and checks the selected ascended origin and unlocked ascension flag.

`ProgressionData.load/save` use the target `HolderLookup.Provider` signatures. The exact target NeoForge SavedData implementation already deep-copies the returned save compound before dispatching asynchronous disk IO; another full global-provenance copy in this mod would add avoidable work. Saved keys/formats were not renamed or discarded. Persistent provenance and discovery histories intentionally grow with explored/touched world area and must not be size-evicted, which would reopen XP farming.

## Validation status

- Added two pure JUnit regression cases in `ProgressionMathTest`.
- Extended the existing **opt-in disposable dedicated-server** `DirectXpSmoke` with `DirectXpAuditSmoke`; success marker: `TNK_XP_AUDIT_SMOKE_OK`. It never runs on a normal server without the existing smoke system property.
- Extended `StarcatcherSmoke` to call the actual transformed mod method for common/rare/epic/legendary catches, a repeated completed invocation, a failed minigame, an already-paid live bob, and an original-method exception with a real pending attachment/bob context. The last test verifies `finally` cleanup and no partial award. It is skipped when Starcatcher is absent and runs inside the same opt-in fixture.
- Shared build/runtime execution is performed by the root audit worker. At the time this note was written, these new checks were prepared but had not yet been run by this worker. The final validation report must use the actual root build/log results, not infer success from source review.
- No human-controlled in-game/client testing was performed by this worker. The source audit and automated fixture are distinct from a live modpack playtest, disk-restart/reconnect test or a controlled TPS benchmark.
